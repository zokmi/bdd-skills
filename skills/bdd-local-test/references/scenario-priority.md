# 情境等級與必測範圍

## 情境等級

用業務結果失效時的影響分級。在 `Scenario`／`Scenario Outline` 上標記一個大寫等級。Outline 的範例共用該等級。依實際業務影響選擇符合的最高等級。

| 等級 | 判準 | 例子 |
| --- | --- | --- |
| `@P0` | 核心業務無法完成且沒有可接受的替代方式，或可能造成越權存取、敏感資料外洩、重大資料損失或交易錯誤 | 未授權角色無法讀取其他租戶資料，付款結果正確 |
| `@P1` | 正常功能、適用的驗證、業務狀態或錯誤處理失效，有實質業務影響但未達 P0 | 表單欄位驗證，合法狀態轉換，既有流程相容性 |
| `@P2` | 低影響的輔助行為或可觀察差異，主要工作仍可完成 | 非必要的排序預設、輔助提示 |

- `@core` 仍標記模組主流程，可與等級並存。等級、`@core`、單號與驗證手段各自獨立。臭蟲修好後，情境仍按長期業務影響分級。
- 新增、實質修改業務前提、操作、預期或範例的情境，要補上恰好一個等級。情境等級重複或使用無效的 `@P<數字>` 屬必修。未實質修改的舊情境可保留無標籤，選測暫以 P1 排序。若從需求或 diff 判定為 P0，當輪按 P0 納入並記明依據。

## 按變更類型決定必測範圍

依需求、驗收條件及 diff 判定適用類型。同一變更符合多種類型時，合併各類的必測項目。以下每個項目依實際受影響的行為納入，未適用時在清單註明理由。

| 變更類型 | 應驗範圍 |
| --- | --- |
| 新功能／功能調整 | 覆蓋全部驗收條件和主成功路徑。測適用的輸入邊界、拒絕、角色／權限、狀態轉換或外部整合失敗。核對受影響的既有流程及舊資料相容性。 |
| 臭蟲修正 | 以可判定的症狀和觸發條件固定回歸情境，驗證修正後的業務結果。涵蓋同一規則相鄰的成功、拒絕或邊界，以及原本正常且共用受改邏輯的路徑。 |
| 資安變更 | 採 HIGH／FULL。驗證允許的角色仍能完成合法操作、應拒絕的角色無法取得受保護資料或改變狀態，以及受影響的租戶或資源隔離。若需求涉及工作階段生命週期、保護資料或稽核紀錄，逐項驗證其預期。使用授權的測試角色、測資與環境驗證安全控制的結果。 |
| 資料庫 Schema／資料遷移／修復 | 採 HIGH／FULL。技術驗證依實際部署分支涵蓋表不存在、空舊表、非空舊表、已升級重跑。驗證資料保留與映射、失敗停止及交易 rollback。非空舊表若無法安全推導新歸屬，驗證會中止並保留資料及結構。另驗受影響業務流程的可觀察結果。 |
| 重構／依賴／設定／部署 | 執行適用的靜態、建置、啟動、相容性或設定檢查。驗證共用元件依賴的核心路徑及受影響回歸。無法界定影響時採 FULL。純文件改動依既有 FAST 條件判定。 |

## 從計畫到派工

1. 依 [品質閘門](quality-gate.md) 決定輪次範圍。TARGETED 的腳本輸出是候選清單，規劃者必須依本規範補齊。FULL 保留所有模組情境，並另外核對應做的技術驗證。
2. TARGETED 必測包含受本次變更影響的 P0（含依賴路徑）、受影響模組的 `@core`、本單新增或修改的情境、對應驗收條件及上表必測項的情境，以及必要回歸。即使是 P2，直接受影響也納入。略過情境須以需求、diff 或依賴分析說明理由。純工程驗證可逐項列入清單，情境編號填不適用。
3. 開發回饋先驗修正、直接受影響的資安或資料保護行為及相關回歸。其餘項目可依 [驗證階段](execution-workflow.md) 記錄延後理由與安排。最終驗證涵蓋全部驗收條件與適用必測項，符合 FULL 條件時執行全套。
4. 在 `REPORT.md` 的〈預計驗證項目〉記錄變更類型、適用的必測項目、選入的情境與等級、各項斷言或技術驗證、以及略過理由。必要項目未跑、阻塞或缺證據時，記錄實際狀態，最終驗證不得宣告全通過。範圍無法確認時依品質閘門升為 FULL。
