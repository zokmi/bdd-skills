# BDD 版控分工

Git 保存持續維護的規格；每輪執行結果由完整封存包保存。維持現有 `.bdd/<單號>-<主題>/` 輸出路徑，不改腳本介面。

| 項目 | 保存方式 |
|------|----------|
| `.bdd/modules/**/*.feature`、`MODULE.md` | Git，隨程式修改提交 |
| `.bdd/config.json` | Git，僅限共用設定；帳密與個人路徑不提交 |
| `.bdd/<單號>-<主題>/` 全部內容 | 本機輸出及完整封存，包含報告、驗證紀錄、遮罩紀錄、截圖、log 與瀏覽器 profile |
| 封存 ZIP 與 `index.jsonl` | repo 外封存庫；已授權時上傳 issue |

## 忽略規則

依專案規範更新 `.gitignore`；已有明確相反規範時先回報差異，不自行覆蓋。建議以預設排除、明確保留的方式避免新增執行產物誤入版控：

```gitignore
/.bdd/*
!/.bdd/modules/
!/.bdd/config.json
```

檢查模組子目錄沒有被其他規則忽略，並以 `git check-ignore -v --no-index <路徑>` 核對報告被排除、模組情境及共用設定可追蹤。若專案整個忽略 `.bdd/`，需先調整父目錄規則才能保留 modules；不要用 `git add -f` 繞過。

提交時明列本次程式、模組情境與共用設定路徑，不使用 `git add .` 收進執行產物。不為服務停止、issue 上傳或封存結果另建純報告 commit；受測版本以程式與情境 SHA 記錄。

## 已追蹤輸出的遷移

`.gitignore` 不會停止追蹤既有檔案。先確認指定輸出的完整 ZIP 已建立、雜湊驗證成功且可還原；合併收尾模式還須確認 issue 附件可下載。尚未完成時保留原始資料。

有明確遷移授權後，列出 `git ls-files -- .bdd/<單號>-<主題>/`，只對核對過的輸出路徑使用 `git rm --cached -- <檔案>`，保留本機內容。不要遞迴移除整個 `.bdd/`，不要改寫歷史。停止追蹤的刪除項目與 `.gitignore` 為一次性遷移提交；其他 repo/worktree 不自動遷移。

未授權遷移的已追蹤報告保留在工作區，不自動提交其更新、不丟棄異動。若因此無法取得乾淨整合工作區，回報待遷移項目；不能將它夾帶進程式提交或強行清理 worktree。

## 複測與保存

`verification.json` 仍須逐輪產生；情境仍需先 commit，封存腳本才能從受測 SHA 取出快照。只保留報告模式保存本機輸出，使用者要求封存時才封存，不額外上傳。團隊共用結果以已確認可下載的 issue 附件為入口；本機封存路径不能充當團隊可用連結。
