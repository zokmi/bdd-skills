# BDD 情境合規檢查

此審核唯讀，只評估指定版本與範圍的文件。**已受派的獨立審核者**直接依[審核清單](references/reviewer.md)執行 lint、人工檢查與回報。派工及後續修正由主代理負責。

## 主代理

1. 使用者直接要求稽核既有文件時，派未參與撰寫或修改的唯讀子代理。任務中新增、修改、刪除、改名、整併 `.feature` 或異動影響歸屬與規則的 `MODULE.md` 時，在一組相關修改完成後自動派審。外部編輯由代理下次接續異動時補審。
2. 派工只需給出 repo、範圍、基準及候選 commit／未提交 diff（既有文件記工作區狀態）、原始需求的取得方式或缺件，以及[審核清單](references/reviewer.md)的實際路徑。範圍包含刪除造成的覆蓋影響及同功能的重複、矛盾。讓審核者獨立判斷結論。
3. 若已有合格的獨立情境審核者，可同一次派工，分別記錄文件合規與既有審核結論。相同版本、範圍與規則可沿用結果。缺少獨立子代理時回報 `待確認／阻塞` 及原因。
4. 依既有修正授權處理問題，修正後重新 lint 並獨立複審受影響範圍。仍有必修或待確認時，保留材料並停止進入實測。有本輪報告時記入〈情境審核〉，否則在對話回報；僅依使用者要求另存報告檔。
