# Issue 回覆內容審核

每次完成已授權的 issue 回寫並回讀後，主代理自動派一名未參與該回覆撰寫、寫入或更正的唯讀子代理審核。審核者直接讀取指定 issue 上已儲存的註記及附件。派工時提供 issue 與註記識別、本次已驗範圍、原需求、受測版本與 diff、已審核的報告、逐項證據、適用的 issue-writing skill 驗證完成模板與使用者對回覆方式的明確要求。審核者只回報結論，由主代理協調後續處理。

## 逐項核對

1. 內容完整性依[逐條回覆驗收標準](../bdd-local-test/references/closeout.md#逐條回覆驗收標準)審核。定位已刊登的註記，核對它聲稱通過的範圍。同單多次回饋時，從這一批回饋、對應的原單條號及本批 diff 逐項反查實測結果與必要回歸。本批內仍待驗的子條件要點名；先前批次只在再次受影響時要求本版證據。若引述歷史結果，核對原輪次及受測版本。確認本批各項結果均有同版證據，且回覆陳述的範圍相符。宣稱整單驗收通過時，改從原單及後續回饋累積的全部有效驗收條件反查；若有缺項或用不同版本的結果拼成整單通過，判 `FAIL`。
2. 依 issue-writing skill 的驗證完成模板核對已刊登註記。一般 UI 可用本輪報告中的實際操作與觀察值支持逐項結果。需目視比對或使用者、模板、核准清單已要求的圖片，依本次交付格式核對附件、引用及遮罩。從報告核對圖片的輪次、版本與擷取條件，如角色、操作狀態及視窗尺寸，再目視確認結果。同圖支持多條時，逐條核對圖中可見的值或位置。純 API／DB／檔案項目核對實際值與來源，混合條件分別核對畫面及資料。
3. 審核輸出列明 Redmine 預設版的「其他資訊補充」是否涵蓋所有未驗證與待確認項目，以及首次回寫有無遺漏外觀相同圖片的前置狀態差異與佐證來源。使用者明確要求精簡時，依模板核對逐項文字與本輪核准的本機證據，仍要指出漏列的未驗證及待確認項目。
4. 回傳審核者、issue／註記識別、階段與受測版本，依原條號列出回覆位置、結果、對應證據、缺漏及結論。可確認的漏列、錯誤、錯圖或過度宣稱，回報 `FAIL` 並指出確切項目。只有草稿、寫入者轉述，或受權限、工具限制無法查證必要的線上呈現或證據，回報 `BLOCKED` 及原因。全部核對相符才給 `PASS`。

## 更正與收尾

主代理將結論記入本輪報告。`FAIL` 時由具寫入授權的代理更正已指出的項目。站台僅能追加註記時，以原註記識別連結更正，保留歷程。重試先回讀已存在的內容，只補缺項。更正後重新讀取並交獨立子代理複審。`BLOCKED` 時保留服務、工作區及必要證據，處理存取或資料缺口。已核對的回覆、附件或其對應的受測結果變更時，須重審受影響的內容。

取得該次實際回覆的 `PASS`，主代理才可依[收尾指引](../bdd-local-test/references/closeout.md#服務停止)停止符合條件的本輪服務，並於分支方式未定時詢問使用者。仍有測案使用服務時繼續保留。已指定分支方式則沿用既有選擇。限定本機報告或本輪未授權回寫時，主代理記錄 `N/A` 與原因並沿用本機收尾流程。
