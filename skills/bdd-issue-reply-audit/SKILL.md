# Issue 回覆內容審核

每次完成已授權的 issue 回寫並回讀後，主代理自動派一名未參與該回覆撰寫、寫入或更正的唯讀子代理審核。審核者直接讀取指定 issue 上已儲存的註記及附件。派工時提供 issue 與註記識別、本次已驗範圍、原需求、受測版本與 diff、已審核的報告、逐項證據及適用回覆模板。審核者只回報結論，由主代理協調後續處理。

## 逐項核對

1. 定位該階段已刊登的回覆及適用的更正註記。從工單概述的完整驗收標準依原序逐條反查；無獨立章節時使用原單明列的需求。每條及其子條件都要找到對應的實際結果，與需求、實際差異、同版實測斷言及該階段模板核對。限定範圍或未驗的子條件要點名，階段註記須交代待驗回歸。原單仍有缺項而回覆宣稱本單全過，判 `FAIL`。
2. 審 Redmine [逐條附圖的註記](../bdd-local-test/references/closeout.md#逐條回覆驗收標準)時，檢視已刊登註記的渲染結果，逐項確認圖片在對應結果下可見，目視核對畫面值、狀態及受測版本的證據。同圖重用也要分別支持各條說明。只有檔名、一般連結、附件列、集中貼在文末或破圖，都判 `FAIL`。純 API／DB／檔案內容核對項下記載的實際值與來源；混合條件分別核對畫面及資料。
3. 回傳審核者、issue／註記識別、階段與受測版本；依原條號列出回覆位置、結果、項下圖片顯示情況或替代證據、缺漏及結論。可確認的漏列、錯誤、錯圖或過度宣稱，回報 `FAIL` 並指出確切項目。只有草稿、寫入者轉述，或受權限、工具限制無法查證必要的線上呈現或證據，回報 `BLOCKED` 及原因。全部核對相符才給 `PASS`。

## 更正與收尾

主代理將結論記入本輪報告。`FAIL` 時由具寫入授權的代理更正已指出的項目。站台僅能追加註記時，以原註記識別連結更正，保留歷程。重試先回讀已存在的內容，只補缺項。更正後重新讀取並交獨立子代理複審。`BLOCKED` 時保留服務、工作區及必要證據，處理存取或資料缺口。已核對的回覆、附件或其對應的受測結果變更時，須重審受影響的內容。

取得該次實際回覆的 `PASS`，主代理才可依[收尾指引](../bdd-local-test/references/closeout.md#服務停止)停止符合條件的本輪服務，並於分支方式未定時詢問使用者。仍有測案使用服務時繼續保留。已指定分支方式則沿用既有選擇。限定本機報告或本輪未授權回寫時，主代理記錄 `N/A` 與原因並沿用本機收尾流程。
